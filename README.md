# Zalea Weather · 红米手表 5 (Vela JS 应用)

给 **红米手表 5 (REDMI Watch 5) eSIM 版** 做的天气快应用。用 Vela JS 应用框架
（`.ux` 单文件组件）写，走 `@system.fetch` 发 HTTPS 请求取天气。

核心诉求是**离线可用**：选城市完全走内置城市表，不联网；天气数据抓一次就整体落盘，
断网时照常显示，并明确标出"离线"和数据的抓取时间。

天气**能看预报**：主页底部一条三日概览，点它进 **7 天预报页** —— 每天一行，
有日期、星期、天气图标、天气文字、最高/最低温和降水概率。预报页**只读缓存、不联网**，
所以断网也能翻。

## 屏幕适配

红米手表 5 的屏幕参数（来自官方多屏适配文档）：

| 项 | 值 |
|---|---|
| 形状 | 矩形 |
| 分辨率 | 432 × 514 |
| PPI | 324 |
| 屏幕宽度 (DP) | 216 |
| DPR | 2.0 |

`manifest.json` 里设 `designWidth: 432`。**注意这里和手机快应用不一样** ——
手机的 `designWidth` 默认是 750，手表是 480（模板默认）或直接写设备宽度。
设成 432 后，样式里的 `px` 就等于物理像素，布局可以按像素精确排布
（但纵向可用高度不是 514，见下面坑 1）。

### ⚠️ 两个只有跑起来才会发现的布局坑

下面两条都是我在模拟器上真跑起来、逐像素量出来的。**静态看代码完全看不出来**，
而且都不会报错，只会安静地把内容截掉。

**坑 1：快应用拿到的可绘制区是 432×466，不是 432×514。**

LCD 确实是 514 高（`config.ini` 和 `hardware-qemu.ini` 里都写着 514），但底部约 48px
被系统占掉了。我把页面涂红、底栏涂绿实测：红色只画到 y=458，绿色只露出 8px，
y≥467 全黑。所以任何"按 514 排满"的写死布局，底栏都会掉出可视区。

修法是把**能屈能伸的行改成 `flex-grow`**，不写死高度：

```
页面级：顶栏 64 + .body(flex-grow) + 底栏 56      -> .body 分到 466-64-56 = 346
.body 内：.hero(flex-grow) + 三格 92 + 预报 116    -> .hero 分到 346-92-116 = 138
```

这样在 466 和 514 两种高度下都不会裁切。城市页同理，`.lst` 用 `flex-grow`。

**坑 2：Vela 的 `width: 100%` 是 content-box，padding 不算在里面。**

`width: 100%`（=432px）再配 `padding: 0 24px` 的元素，实际占 **480px**，
右边 48px 直接被切出屏幕。实测证据：角标背景色 `#16302A` 一直画到 x=431，
卡片跨 x=29..431，而设计值是 29..403。

修法是**左右留白一律用 `margin-left` + 显式宽度，不用 padding**：

```css
/* 不要这样：.hdr { width: 100%; padding: 0 24px }        -> 实际 480px，右侧被切 */
.hdr { width: 384px; margin-left: 24px; }   /* 432 - 24 - 24 = 384 */
```

改完重测，卡片落在 **x=29..402**（设计值 29..403），对上了。

`lint.mjs` 里现在有断言盯着这两条：`width:100%` 的元素不许有左右 padding；
所有带 `margin-left` 的定宽块右边缘不许越过 432；`.body`/`.hero`/`.empty`/`.lst`
必须是 `flex-grow` 且不能同时写死高度。

### 卡片之间的那道缝

详情行和预报行的**卡片高度比所在行容器小**，差额做成了上边距，这样两行的卡片之间
才有一道 8px 的缝（`cell` 78+14、`fc-col` 108+8）。如果让卡片撑满容器，两行的
六个卡片会紧贴上，视觉上融成三根长条、分不出是哪一行 —— 这是渲染整页预览时
才看出来的问题。`lint.mjs` 里也有断言盯着这条算术。

## 构建

```bash
cd vela-weather
npm install          # 装 aiot-toolkit（实测 39 秒 / 717 个包）
npm run start        # 开发：aiot start --watch
npm run build        # 调试构建
npm run release      # 发布构建（需要 sign/ 下的证书，见下）
```

产物在 `dist/`，**已构建成功**，两个包都已生成：

| 文件 | 大小 | 说明 |
|---|---|---|
| `dist/com.zalea.weather.debug.1.0.0.rpk` | 44630 B (43.6 KB) | 调试包，工具链自带证书签名 |
| `dist/com.zalea.weather.release.1.0.0.rpk` | 33646 B (32.9 KB) | 发布包，用 `sign/` 里的自签证书签名 |

> 包名 `com.zalea.weather` 和显示名 `Zalea Weather` 都在 `src/manifest.json` 里。
> **改包名 = 装成一个新应用**：旧包不会被覆盖，得先手动卸掉；应用自己存的
> storage（上次选的城市）也不会跟过来，重装后回到默认城市。只改显示名不动包名的话
> 就能原地升级 —— 按需取舍。

**两个包都在模拟器上装过、跑起来了**（`release` 那个也验过，见下面「在模拟器上跑」）。

> ⚠️ **`aiot build` 和 `aiot release` 都会清空 `dist/`。** 后跑的那个会把先跑的产物删掉。
> 要同时保留两个包，跑完一次就先把 `.rpk` 拷到别处。仓库里这两个是我分别构建后另存的。

编译器对项目本身**零警告零错误**。它只提出过一条真实问题：`index.ux` 里
`saveCityName` 导入未使用（城市名是 `city.ux` 负责写的，主页只读），已删。

顺带验证了一件本来没把握的事：`designWidth: 432` 是**原样透传**的 ——
编译产物里 CSS 的 `394px` 还是 `394px`，编译器没有做任何按比例缩放。
这正是"样式里的 px 等于物理像素"这个前提成立的原因。

### 关于签名

`aiot build`（debug）用工具链自带的证书，不需要你准备什么。
`aiot release`（production）**必须**有证书，否则会失败：

```
Error: The current mode is production, and there is a problem with the certification path
```

证书自己生成即可，放 `sign/` 根目录（**已实测**：`sign/private.pem` + `sign/certificate.pem`
就能被找到，不需要再建 `sign/debug`、`sign/release` 子目录）：

```bash
openssl req -newkey rsa:2048 -nodes \
  -keyout sign/private.pem -x509 -days 3650 -out sign/certificate.pem \
  -subj "/C=CN/O=Self/CN=vela-weather"
```

> **Windows / Git Bash 用户注意**：上面这条命令在 Git Bash 里会报
> `subject name is expected to be in the format /type0=value0/...`。
> 原因是 MSYS 把 `-subj "/C=CN/..."` 里的 `/C=CN/...` 当成路径，改写成了
> `D:/Git/C=CN/...`。前面加 `MSYS_NO_PATHCONV=1` 即可：
>
> ```bash
> MSYS_NO_PATHCONV=1 openssl req -newkey rsa:2048 -nodes \
>   -keyout sign/private.pem -x509 -days 3650 -out sign/certificate.pem \
>   -subj "/C=CN/O=Self/CN=vela-weather"
> ```

`sign/` 已经进了 `.gitignore`，别把私钥提交上去。仓库里现在这份是我生成的自签证书，
**建议你换成自己的**（自签证书只对本机/本人有意义）。

## 在模拟器上跑（`aiot start`）

`aiot-toolkit` 自带一个 Vela 模拟器，**这是真的 Vela OS** —— NuttX RTOS 跑在 QEMU 里，
用的是官方 `vela-miwear-watch-5.0` 系统镜像，不是 Android 模拟器。所以它验证的东西
比"编译通过"多得多：`@system.fetch` 真发 HTTPS、布局真渲染、rpk 真安装。

```bash
npx aiot initEmulatorEnv     # 下载模拟器 SDK，约 2.1 GB，只跑一次
npx aiot createVVD           # 建虚拟设备（第一次会问分辨率，见下面坑 2）
printf 'y\n' | npx aiot start    # 启动。注意别用 yes，见坑 1
```

启动后 adb 在 `127.0.0.1:5555` / `emulator-5554`，调试口 10055。

### 踩过的坑

1. **`yes '' | npx aiot start` 会把 Node 撑爆。** `yes` 无限输出空行，全被读进
   Node 堆里，4GB 堆打满后 `FATAL ERROR: Ineffective mark-compacts near heap limit`，
   qemu 根本没起来。改成 `printf 'y\n'` 喂一行就够了。

2. **`aiot createVVD` 的分辨率校验有 bug**，某些输入下会拒绝合法值。
   我写了个 `mkvvd.mjs` 直接生成 `.vvd` 绕过去。

3. **VNC 是死代码，连不上。** `emulator/lib/emulatorutil/constants.js` 里的
   `defaultVncPort = 5900` 从来没被用上 —— `getVvdStartCmd`（`vvd/index.js:404-452`）
   压根没往 qemu 命令行里传 `-vnc`。另外 `index.js:511` 会**复用已在运行的模拟器**，
   所以 `--openVNC` 也不会有任何效果。别在这上面浪费时间。

4. **它是 NSH，不是 Android shell。** 没有 `screencap`，`am` 的用法是
   `am <start|stop> <包名>`，`pm` 是 `pm <install|uninstall> [包名|rpk路径]`，
   `adb shell force-stop` 是无效命令。`ls -l` 的输出格式也和 Android 不一样。

5. **`C:\WINDOWS\system32\adb` 是个空壳**（执行 `version` 没有任何输出）。
   用工具链自带的那个：
   `node_modules/@aiot-toolkit/emulator/node_modules/@miwt/adb/bin/win/adb.exe`。

6. **在 Git Bash 里 `adb push` 会"假成功"。** 客户端打印
   `1 file pushed, 0 skipped`，但**文件根本没落到设备上**，紧接着报
   `failed to read copy response: EOF`。原因是 MSYS 把设备端路径 `/data/app/x.rpk`
   当成 Unix 路径改写成了 `D:/Git/data/...`。加 `MSYS_NO_PATHCONV=1`
   并把**本地路径写成 Windows 形式**就好了：

   ```bash
   export MSYS_NO_PATHCONV=1
   ADB=node_modules/@aiot-toolkit/emulator/node_modules/@miwt/adb/bin/win/adb.exe
   "$ADB" -s emulator-5554 push "C:\...\dist\xxx.rpk" /data/app/com.zalea.weather.rpk
   "$ADB" -s emulator-5554 shell "pm install /data/app/com.zalea.weather.rpk"
   ```

   安装成功时 `pm install` **不会打印任何东西** —— 工具链是靠读设备日志里的
   `executeInstall: rpk install: ... success` 判断的。装完那个 `.rpk` 会被安装器吃掉
   （`/data/app` 里不再有它），这本身就是成功的标志。

7. **截图：别截窗口，走模拟器自己的控制台。** NSH 里没有截屏命令，所以第一反应是对
   QEMU 的窗口句柄调 Win32 `PrintWindow(hwnd, hdc, 2)`。这条路**一开始能用，后来彻底
   不行了** —— 返回 `False`、像素全黑，最小化再恢复（`IsIconic` → `ShowWindow(h,9)` +
   `ShowWindow(h,5)`）重试 8 次全败。同一时期 `CopyFromScreen` 更糟：它截到的是**压在
   最上面的那个窗口**（实测截回来一张终端），因为后台会话里 QEMU 窗口根本不是前台窗口。

   能用的是模拟器自己的控制台截屏 —— 这是**宿主机侧的抓取，不经过窗口，所以不怕遮挡**：

   ```bash
   # 端口是 5554（adb 那个 5555 是它的下一号）
   printf 'auth %s\nscreenrecord screenshot <目录>\ndetach\n' \
     "$(cat ~/.emulator_console_auth_token)" | nc 127.0.0.1 5554
   ```

   几个细节：目录用**正斜杠**（反斜杠会被吃掉）；目录得**先建好**，不存在就静默什么都不写；
   令牌在 `~/.emulator_console_auth_token`。产出 `Screenshot_<时间戳>.png`，
   尺寸正好 **432×514**，就是真实 LCD，**不带任何窗口边框** —— 比截窗口干净得多，
   量像素时不用先减掉标题栏和边框。

8. **合成点击是条死路（三条路都试过了）。** 想在模拟器上模拟一次点按，以下全部无效：

   | 手段 | 结果 |
   |---|---|
   | `PostMessage` 发 `WM_LBUTTONDOWN/UP` | 点底栏（`onclick="refresh"`）前后两张截图**逐像素相同，0 个像素变化** |
   | 控制台 `event mouse <x> <y> <device> <buttonstate>` | 回 `OK`，快应用**收不到** |
   | 控制台 `event send EV_ABS:ABS_MT_*` + `BTN_TOUCH` + `EV_SYN:0:0` | 同样回 `OK`，同样收不到 |

   第三条有两个坑值得记：`event codes EV_SYN` 会报 "no code aliases defined for this
   type"，`EV_SYN` 必须写成**裸数字** `EV_SYN:0:0`；即便如此，事件注进去了也到不了快应用。
   另外 `SetWindowPos(HWND_TOPMOST)` / `SetForegroundWindow` 都不能把 QEMU 窗口提到前台。

   结论：**这台环境下没法从外部驱动 UI**。"点一下能不能进预报页"只能在
   `test/t6_page.mjs` 里断言处理器绑没绑、`push` 的 uri 对不对（见文末「验到什么程度」，
   那里说明了这个断言的边界）。

   但**应用自己驱动自己是可行的**，切城市那次就是这么做成的：让页面用 `setTimeout` 走到
   目标动作再 `router.back()`。不过这里还埋着一个坑 —— **页面被盖住之后，它的定时器就
   不再触发了。** 上面那个自驱动脚本第一版把"返回"写在**主页**的定时器里（`push` 进城市页
   → 主页 `setTimeout` 2 秒后 `router.back()`），结果应用**卡在城市页再也出不来**：
   `push` 把主页盖住，主页的定时器随之被挂起，`back()` 永远等不到；14 帧截图里后 9 帧全是
   城市页。这是**刺激器把自己锁死了，不是应用的 bug** —— 真机上 `back` 是用户手指按的，
   不靠定时器活着。把触发点挪到**可见的那一页**（城市页 `onShow` → +2.5s → 选城市 →
   `back()`）立刻就通了。要写这类自驱动脚本，记住：**只有当前可见页面的定时器在跑。**

9. **字库里没有 `›`（U+203A）。** 主页预报条右侧那个"更多"箭头，一开始用的是 `›`，
   结果在表盘上**一个像素都没画出来**。编译产物里 `width`、`color` 都在，
   但那一格整块是背景色 —— 字体里没有这个码位，**缺字是静默的**：
   编译过、lint 过、静态检查全绿，只有盯着表盘才看得出来。换成 ASCII `>` 就正常了。

10. **`@system.storage.get` 的回执形状和文档写的不一样。** 文档说 `success(data)` 里
    `data.data` 才是值；这台表上**直接把值本身当第一个参数递进来**
    （`JSON.stringify` 出来是 `"\"RT1789...\""`，不是 `{"data":"RT1789..."}`）。
    只认 `{data:...}` 的写法会让**读永远返回空、而 `set` 照样报成功** ——
    表现是主页一切正常、缓存看着写了其实读不回来、预报页永远"还没有数据"。
    现在 `unwrap()` 两种形状都认，`test/t9_regress.mjs` 两种都跑一遍。
    顺带记一笔：`sysstorage.js` 这个桩**默认就按真机的 `bare` 形状返回**，
    因为以前它按文档返回 `{data:}`，于是这条 bug 在测试里一路绿灯。

11. **属性值里一个裸的 `>` 会让整个部件不渲染。** 图标部件的显隐本来写的是
    `if="{{ic.drops > 0}}"`，结果毛毛雨/小雨的**雨点一个像素都没有**，
    而同一份配方里没有 `>` 的 `cloud`/`cloud2` 都正常。
    现在比较一律在 JS 里算好布尔值（`wmo.js` 的 `d1..d3`/`f1..f3`/`g1..g3`），
    模板只读布尔；`lint.mjs` 里加了断言，模板表达式里出现 `<` 或 `>` 直接报错。

12. **百分比几何在 108px 上没问题，在 40px 上会散架。** 图标两套配方：
    `.ic-lg`（108px 主视觉）用百分比（`.p-*`），`.ic-sm`（40px 预报）用整数像素（`.s-*`）。

    右边缘切掉，雨点和云底座干脆没有。同一份配方在 108px 上完全正常。
    40px 下百分比会落到 `14.4px` 这种小数上，多半就折在这里。
    换整数像素后 12 种天气全对（见 `preview/icons.png` 右列）。
    `lint.mjs` 现在按前缀分别校验两套配方，并要求两套的部件名完全一致 ——
    小图标少一条规则只会坏预报页，主页看着完全正常，最容易漏。

## 离线是怎么做到的

三层：

1. **选城市不联网。** `src/common/cities.js` 内置 105 个城市，名字、省份、拼音、
   经纬度、中国天气网城市码全在本地。搜索、切换城市全程零网络请求。

2. **天气数据整体缓存。** 每次抓取成功，把整个数据模型 `JSON.stringify` 后写进
   `@system.storage`。启动时**先渲染缓存**，再在后台刷新 —— 所以打开即有内容，
   不会先白屏再跳数据。

3. **断网降级可见。** 抓取失败时不报错刷屏，而是保留当前画面、打上「离线」角标，
   底栏显示缓存数据的抓取时间。用户能明确知道自己看的是旧数据。

### 两个刻意绕开的坑

- **抬腕亮屏会触发 `onShow`。** 如果在 `onShow` 里无条件重新抓取，
  每抬一次手腕就打一次网络，非常费电。这里只在缓存超过 20 分钟时才自动刷新。
- **`@system.fetch` 没有超时参数。** 文档里没有，所以用 `Promise.race` 自己加了
  9 秒超时，避免网络不好时一直挂着。

## 7 天预报页

主页底部那条三日概览**整条可点**（不是只有右边那颗 `>` 小胶囊），点进 `/pages/forecast`。
每行是「日期 + 星期」+ 天气图标 + 天气文字 + 高低温，下面一行小字是降水概率和风向风力。
7 行放不下一屏，用 `<list>` 滚动。

两个设计决定：

- **预报页只读缓存，自己不发请求。** 它显示的就是主页此刻那份数据，两页永远不会打架。
  打开即出内容，断网也能翻。**但缓存得对得上城市** —— 切了城市又没抓到新数据时，
  缓存里还留着旧城市的 7 天预报，这时预报页会拒绝显示，明说"还没有 上海的 预报 /
  缓存是北京的"，而不是把北京的预报挂在上海名下（见下面「切不了城市」）。
- **数据只存一份。** 落盘的是 `city/src/ts/now/today/forecast`，`days`（三日概览）和
  `icNow`（图标开关）都是读的时候由 `withIcons()` 重算的 —— 不存第二份，
  免得主页那条概览和预报页迟早对不上。`t4` 里有断言盯着"派生字段不落盘"。

走兜底源（中国天气网）时没有多日预报，这时概览条会显示"备用源无多日预报"而不是空白。

## 「切不了城市」这个 bug

**症状**：在城市页选了新城市、返回主页，顶栏还是旧城市。必须杀掉应用重开才生效。

**根因不在城市页，而在主页的 `onShow`。** 城市页一直是对的 —— 它老老实实把新城市
写进了 `@system.storage`。问题出在主页这边同时踩了三个坑，每个单独看都"说得通"：

1. **`onShow` 只判"缓存过期才刷新"。** 主页的 `onShow` 是这么写的：

   ```js
   if (this.hasData && !cacheFresh(this.model)) this.pull(false)
   ```

   这条规则本身是为了省电（抬腕亮屏也会触发 `onShow`，不能每次抬手都打网络，
   见上面「两个刻意绕开的坑」）。但用户刚在城市页选完城市时，**缓存恰好是新鲜的** ——
   于是整个 `onShow` 什么都不做，城市页写的那个名字根本没机会被主页看见。

2. **主页只认 `this.city`，而它只在 `boot()` 里读过一次存储。** `boot()` 在
   `onInit` 时跑，`onShow` 不会重新读。所以就算用户切了城市，`this.city` 还是旧的，
   连手动点底栏刷新也没用 —— `refresh()` → `pull()` → `findCity(this.city)`
   拿的还是旧城市。只有重启应用才能让 `boot()` 重读一次。

3. **`apply()` 里有一句 `this.city = model.city || this.city`，把分歧固化了。**
   它让"最后返回的那份响应说了算"。于是即使重启，一份晚到的旧城市响应也会把城市
   顶回去；更糟的是切换时若新数据没抓到，旧城市的数据会挂在**新**城市的标题底下 ——
   顶着"上海"显示北京的 27°，比空着更让人摸不着头脑。

**修法**（四点，都在 `src/pages/index/index.ux`）：

- **`onShow` 改成先读一次存储、比对城市变没变**（新增 `syncCity()`）。
  读存储不发网络，所以抬腕亮屏的省电设计原样保留：城市没变就还是走"缓存过期才刷新"。
  为了不和启动时的 `boot()` 抢着取数，加了一道 `ready` 闸门 —— 应用刚起来时
  `onShow` 会先于 `boot()` 里的 `await` 跑一次，那时城市还没定下来，直接返回。
- **切城市时先把旧数据清掉**（新增 `dropData()`），宁可空着显示"正在获取 上海的天气…"，
  也不让旧城市的数据顶着新城市的名字。
- **请求回来时核对是不是当前城市**：`if (city.n === this.city)` 才 `apply` + 写缓存，
  失败同理。晚到的旧城市响应直接丢掉。
- **`pull()` 里在途请求不再吞掉新的切换**：以前是 `if (this.busy) return`，
  正好在抓旧城市时切城市就被静默丢弃、新城市永远排不上队。现在记一个 `pending`，
  等前一个请求结束再补一次。

另外两处配套改动：

- **`saveCityName()` 改成返回 Promise**（最多 300ms 兜底，绝不挂住），城市页
  `pick()` 里 `await` 它再 `router.back()`。`storage.set` 是异步落盘的，
  写完立刻读可能读回旧值，而主页回来时是"立刻就要读"。
- **缓存按城市归属校验**：`boot()` 要求 `cached.city === this.city` 才铺缓存；
  预报页同样拒绝显示属于别的城市的缓存，改为明确说"还没有 上海的 预报
  / 缓存是北京的"。`withIcons()` 会把城市名一并存进缓存，就是为了这个。

**验证**：新增 `test/t10_switch.mjs`（35 项断言），把主页和城市页的 script **一起**加载、
共用一个 storage，配一个会记账的路由栈（`push` 进去派 `onInit`+`onShow`，
`back` 出来对下面那页派 `onShow` —— 和框架语义一致）。取数用可编排的桩，
按请求里的经纬度反查城市、返回该城市专属的温度，于是"数据也跟着切过去了"是被
断言到的：切到上海之后显示的温度必须是上海的 25°，不是北京的 10°。

**这个测试确实能失败**：把 `index.ux` 换回修复前的版本重跑，第 1 节就挂，
报的正是用户看到的那个现象 —— `主页城市名换成上海 -> "北京"`。

### 在真 Vela OS 上验过

模拟器上合成不了触摸（见上面坑 8），所以让应用自己走了一遍用户的动作：主页
`push` 到城市页，城市页停 2.5s 后调 `pick()` 写城市名并 `back()`，返回由框架派发
`onShow`。这样连"框架到底会不会在 `router.back()` 之后派发 `onShow`"也一并验到了
（这是整个修法的前提假设，光看文档不放心）。

抓到的连续四帧：

| 时刻 | 主页顶栏 | 调试条 |
|---|---|---|
| 13:46:32 | 广州 | `D onShow ready=false city=广州` |
| 13:46:40 | **杭州** | `D n=1 saved=杭州 cur=广州` |
| 13:46:49 | **成都** | `D n=2 saved=成都 cur=杭州` |
| 13:46:57 | 成都 | `D onShow ready=true city=成都` |

第二、三行就是结论：`syncCity()` 从存储里读出了新城市并应用了它，顶栏连着换了两次。
第一行 `ready=false` 说明启动期那道闸门也确实拦住了（那次 `onShow` 提前于 `boot()`
的 `await` 跑，被正确忽略）。

> 这里绕了个弯值得记一笔：一开始把"返回"也写成主页自己的定时器
> （`setTimeout(() => router.back(), 2000)`），结果**页面被 `push` 盖住之后它的
> 定时器就不再触发了** —— 定时器随页面隐藏被挂起，`back()` 永远等不到，
> 应用卡在城市页出不来（14 帧截图里后 9 帧全是城市页）。这是刺激器自己把自己
> 锁死了，不是应用的 bug：真机上 `back` 是用户按的，不靠定时器。
> 把触发点挪到城市页（可见页，定时器照常跑）之后就通了。

## 城市数据是怎么来的（以及为什么这么较真）

城市码**不能猜**。猜错不会报错，而是**安静地返回另一个城市的天气** ——
这比直接失败更糟。所以这 105 个城市码是逐个联网核验过的：

1. 逐个请求接口，检查返回的 `cityname` 是否和预期城市一致。
2. 第一轮 105 个里 101 个通过，4 个不匹配：
   - **株洲 / 湘潭** 两个码写反了（真值：湘潭 `101250201`、株洲 `101250301`）
   - **德阳** 是错的（真值 `101272001`）
   - **绍兴** 返回「越城」—— 那是绍兴的中心城区，码本身没错，予以保留
3. 经纬度用 **ECharts 中国地图 GeoJSON 的地级市中心点（`cp`）** 作为权威锚点。

经纬度这一步中间踩了个大坑值得记一笔：一开始用 Open-Meteo 的 geocoding 接口取坐标，
结果**它的中国地理索引被村级地名污染了** —— 大连匹配到海南、长春匹配到黑龙江、
吉林市匹配到台北。更坑的是，中英文两次查询返回的是**同一条错误记录**，
所以「双语交叉验证通过」只证明了一致性，根本没证明正确性。

最后改成：以 GeoJSON 质心为权威锚点，在 geocoding 候选里**挑离锚点最近且同名的那个**；
偏离超过 1.2° 就直接用质心。105 个城市里 55 个通过了地理编码校验、43 个直接用质心，
7 个 GeoJSON 未覆盖的（4 个直辖市、台北、景洪、襄阳）手工补齐。

`src/common/cities.js` 顶部的注释里记了完整的来源和校验方式。

原来的 `run_all.sh` 写成 `node xxx.mjs | grep ... || FAILED`,这个 `||` 挂的是管道
最后一环 `grep`/`tail`,它们基本永远成功 —— 于是**真正的失败被吞掉,脚本照样打印
"全部通过"**。出图那步崩溃时它就是这么骗过去的。现在一律先 `out=$(cmd); rc=$?`
再判断退出码,并且我故意往项目里注入过两处错误(designWidth 改成 750、
body 改成 400px)确认它真的会报失败、退出码为 1,再还原。

## 没做到 / 没验证的部分

诚实交代，避免误以为这是开箱即用的成品：

- **没有在真机（红米手表 5）上跑过。** 这是最大的未知。在模拟器上跑通了、
  逐像素量过了（见上面「在模拟器上跑」），但**模拟器不是手表**：
  - 用的是官方 `vela-miwear-watch-5.0` 系统镜像，跑在桌面 QEMU 里。系统是同一个，
    但屏幕驱动、触控、功耗、真实网络栈都不是。
  - `@system.fetch` 对这两个域名的实际连通性在手表上仍需确认
    （尤其 Open-Meteo 是境外服务器，手表走的是蓝牙/WiFi/eSIM 转发）。
  - 阈值类参数（20 分钟缓存、9 秒超时）在真机网络下是否合适，只有上手才知道。
  - 抬腕亮屏触发 `onShow` 的省电设计，在模拟器上没法验。
- **eSIM 版本未单独验证。** 按官方支持明细表，REDMI Watch 5 是支持
  `@system.fetch` / `@system.network` 的，但 eSIM 机型上第三方快应用的行为
  社区有异常反馈，需要实测。本项目是通用的，没有针对 eSIM 做特殊处理。
- **`aiot start --watch` 的热重载没试过。** 我用的是不带 `--watch` 的
  `aiot start`，以及 `--start-page` 直接启动指定页面。
- **"手指点上去会不会触发"这一环仍然没验，两个页面都没验。** 模拟器上没有任何可用的
  输入注入通道 —— `PostMessage`、控制台 `event mouse`、`event send EV_ABS:...` 三条路
  全试过、全部无效（见上面坑 8）。合成真实鼠标输入会占用你桌面上的光标，我没做。
  所以这一环是拆成两半分别验的：

  - **跳转目标本身**（`openForecast()` / `openCity()` 里 `push` 的 uri）在
    `t6_page.mjs` 里断言（`.fc` 行自己带 `onclick="openForecast"`，`push` 到
    `/pages/forecast`）。**其中进城市页这一半，在真机上也被证实了**：切城市的自驱动
    脚本调的正是 `openCity()`，模拟器截图里城市页实实在在地显示了出来 ——
    说明"处理器一执行，框架就真的会导航过去"，这段链路是真的，不是桩里假装的。
    进预报页那一半没有这样驱动过，只在桩里断言。
  - **预报页本身**以它为入口直接启动跑通了、并逐像素看过
    （截图在 `preview/emulator-forecast.png`）。

  两半合起来，**仍然没验的只有一件事**：手指落在那块矩形里，Vela 会不会把点击派发给
  `onclick`。控件本身是整条 384×116 的预报行，不是右边那颗 30px 的小胶囊 ——
  真机上按行中间任意位置都该触发。
- **`onShow` 在真机上的触发时机只验了一半。** "从城市页返回时框架会派发 `onShow`"
  这一条已经在模拟器上确认了（否则切城市根本不可能通）。但另一半 ——
  **抬腕亮屏也会触发 `onShow`** —— 是照着文档和社区说法做的省电设计，模拟器上
  没有抬腕这个动作，验不了。真机上如果抬腕**不**触发 `onShow`，那这个应用只会退化成
  "数据要手动点底栏才刷新"，不会出错；反之如果抬腕触发的频率比预期高，
  由于城市没变时走的仍是"缓存过期才刷新"（20 分钟），也不会变成每次抬手都打网络。
- **40px 图标已经能看清了，但那是这套几何的下限。** 之前雨滴在 40px 上只有 2.8px、
  基本糊没（见上面坑 12），改用整数像素后雨点是 4px×7px、雪花 5px×5px、
  雾的三条横杠 4px 高，12 种天气在模拟器截图里都能分辨。再往下压尺寸就不行了 ——
  4px 基本是这块屏上还认得出形状的下限。如果以后要更小的图标位，得换更简化的图形，
  而不是把现在这套等比缩小。
- **`system.network` 是防御性声明。** 代码里没有任何地方 import 它，
  但**有可能**被 `@system.fetch` 隐式依赖，而我无法在真机上验证这一点。
  删错了的代价是联网整个失效，留着的代价只是多声明一项权限 —— 所以留着。
  （查过工具链：`node_modules/@aiot-toolkit` 里根本没有 `system.network` 的引用，
  说明编译器只把 features 当不透明元数据透传，既不校验也不推导依赖。）
  相比之下 `system.configuration` 与联网无关又确实没人用，已经删掉了。
- **CSS 用了保守子集。** Vela 的样式限制比普通 CSS 严得多 ——
  不支持后代/子/兄弟选择器、不支持伪类和伪元素、不支持 `*`、
  **不支持多类名交集（`.a.b`）**、`position` 只有 relative/absolute。
  图标因此是"用 `if` 控制各部件显隐"而不是叠类名。几何分两套：108px 主视觉用百分比
  （`.p-*`），40px 预报用整数像素（`.s-*`）—— 同一套百分比在两个尺寸下**并不通用**，
  见上面坑 12。另外没有用 `transform`（不确定是否支持），闪电是用三段错位矩形拼成阶梯状的。
- **图标 `logo.png` 是脚本画的**，不是设计稿，够用但不精致。
- **兜底源没有多日预报。** 中国天气网的 `dingzhi` 接口只给当天，
  所以走兜底时预报栏是空的。
